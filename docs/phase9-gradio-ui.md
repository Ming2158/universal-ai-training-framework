# Gradio 界面使用说明

## 工作区结构

V2.1.0 GUI 使用左侧模块导航，页面在同一个 Gradio 应用内切换：工作台、数据集、训练、训练监控、实验管理、模型管理、评估与推理。训练数据集检查和训练参数分处“数据集”与“训练”；启动后进入“训练监控”，训练仍由独立 CLI 子进程执行，切换到其他模块不会停止任务。数据集设置支持关闭固定尺寸缩放，卷积模型按批次补边；ViT 仍要求开启缩放。训练页提供 DataLoader workers 设置。

实验管理按列表和详情组织，比较位于详情区的二级视图；模型资产独立于实验检查点；独立评估、单图推理和批量目录推理位于“评估与推理”的二级视图。组件行为、配置基线和逐项验收清单见 [`docs/development/gui-ux-audit.md`](development/gui-ux-audit.md)。

### 设计规范

界面采用 `#f4f7f5` 浅绿中性画布、白色内容表面、深色正文与低饱和辅助文字；Gradio 的中性色阶也按同一套边框和表面色调整。主操作/选中态使用绿色，字段标签使用中性文字和透明背景，停止使用危险色，橙色仅作为少量强调。字体使用 Inter 优先并回退到系统无衬线字体；标题、区块标题分别为 25px/16px，间距以 4px 为基数，控件圆角约 5px、面板圆角 6px。页面使用清晰的职责分区、有限高度滚动表格和真实训练曲线。列表突出便于浏览的字段，完整记录保留在详情；没有结果时显示空状态和下一步操作，避免空 JSON、图表和下载控件占满页面。

窄窗口下主要双栏布局会转换为纵向排列。训练配置没有可用数据集时会显示“前往数据集”入口；停止按钮仅在任务状态允许时启用。截图复核后的视觉修正和未完成的浏览器验收项记录在 [`docs/development/gui-ux-audit.md`](development/gui-ux-audit.md)。

## 作用

Gradio 为 UATF 的数据集检查、训练、实验管理、评估和推理提供本地 Web 界面。训练从统一配置生成器写出 YAML 并启动 `uatf.cli` 子进程；数据读取、模型创建、训练、检查点和评估继续使用 `uatf` 底层模块。

## 启动

Windows 用户也可以双击仓库根目录的 `启动UATF.bat`。首次启动会创建 `venv` 并安装 CPU 版依赖，因此需要 Python 3.10、3.11 或 3.12 和网络连接；后续双击会直接启动界面并自动打开浏览器。关闭启动器窗口即可停止服务。

在仓库根目录安装依赖并启动：

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m app.app
```

Gradio 会打印本地访问地址，通常为 `http://127.0.0.1:7860`。

## 数据集 ZIP 格式

上传一个 ZIP 文件，并通过任务选项指定其中一种固定结构。

单标签分类：ZIP 根目录下每个类别一个目录。

```text
dataset.zip
  cats/
    cat_001.jpg
  dogs/
    dog_001.jpg
```

多标签分类：ZIP 根目录下有 `annotations.csv` 和 `images/`。CSV 使用 `image_path` 列加一个或多个标签列，标签值只能是 `0` 或 `1`。

```text
dataset.zip
  annotations.csv
  images/
    image_001.jpg
```

图片数据会按 80%/20% 划分训练集和验证集。小数据集需要保证每个类别在划分后训练集和验证集中都有图片。

## 事件与回调

任务下拉框的 change 事件会更新数据格式提示。Start Training 的 click 回调检查参数、安全解压 ZIP、写出 YAML 配置，并执行 `python -m uatf.cli --config ...`。训练器通过结构化事件报告准备、训练批次、验证批次和 Epoch 完成；GUI 轮询 JSONL 事件文件并增量读取实验日志，不解析终端输出作为训练指标。状态和日志约每秒批量刷新，训练曲线只在 Epoch 完成时更新。

监控面板显示总体进度、阶段、批次、耗时与剩余时间估计、Train/Validation loss、主要验证指标、历史最佳指标、学习率和 Epoch 耗时。逐 Epoch 训练历史与 `metrics.json` 中训练结束后的独立验证集评估分开显示；独立评估使用训练结束时的模型权重。界面保留最近 200 行日志，并提供完整的磁盘日志文件及独立错误摘要/技术堆栈区域。

CPU、系统内存和训练进程资源需要可选的 `psutil`；GPU 利用率、温度和功耗通过可选 NVML 或 `nvidia-smi` 查询。PyTorch 可用时会单独报告 GPU 名称、设备显存和 PyTorch 分配量。缺少监控接口时显示“不可用”，训练仍会继续。可安装扩展监控依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[monitor]"
```

数据集校验、模型创建、训练、checkpoint 保存和评估仍由现有的 `uatf.data`、`uatf.models`、`uatf.training`、`uatf.evaluation` 模块经由 CLI 执行。把 UI 和 Training Engine 分开，可以独立调整操作界面，同时让命令行和 Web 界面运行相同的训练流程。

数据格式、标签、CUDA 不可用、模型名称和 GPU 显存不足等常见错误会显示简明信息。实验目录保留训练日志以便进一步排查。

## 任务、历史与恢复

训练任务以持久任务 ID 记录状态。页面刷新后可查询最近任务；“停止训练”会请求在完整 Epoch 边界停止，并保留最近一个完整检查点。停止不会删除实验文件。恢复时，在 YAML 中设置 `training.resume_from` 指向兼容的 `last_model.pth`，或在历史实验中载入配置后编辑该字段再启动。

历史实验列表支持按名称、模型、状态和日期筛选，并提供配置、指标、日志、检查点和产物信息。旧版实验目录按只读方式读取；目录内容不会被自动搬移或重写。比较实验时，任务、数据集划分、指标或阈值不一致会显示不可直接比较的提示。

## 模型资产、独立评估与推理

历史模型资产可以查看、加载或导出为 PyTorch state-dict 与 JSON 侧车文件。独立评估使用带标签的文件夹或 CSV 数据集，输出指标、预测、图表和错误样本预览，不会改写来源训练记录。单图推理展示类别分数和概率；批量推理读取服务端图片目录并生成 CSV。多标签预测使用可调阈值。

模型资产和实验数据保存在 `OUTPUT_ROOT` 对应的输出目录下。关闭并重新启动 GUI 后，应用会重新读取磁盘中的实验与模型资产记录；训练运行状态来自任务记录，而不是仅保存在浏览器页面中。

## 输出

上传内容、界面生成的配置和训练实验分别写入 Git 忽略的 `outputs/ui_uploads/`、`outputs/ui_configs/` 和 `outputs/ui_runs/`。成功的实验目录包含常规配置、日志、指标和 best/last checkpoint。

## 范围与限制

当前仅支持单标签和多标签图像分类，以及本文说明的文件夹与 CSV 数据集。GUI 只开放共享训练配置的一部分参数；更完整的训练策略可通过 YAML、CLI 或 Python API 配置。恢复只接受兼容的完整训练检查点，推理导出的权重文件不能用于续训。随机划分不是分层或分组划分。CUDA 训练需要与本机驱动匹配的 CUDA 版 PyTorch；小型实验也可使用 CPU。资源采样依赖可选监控接口，缺失时会显示不可用且不阻止训练。
