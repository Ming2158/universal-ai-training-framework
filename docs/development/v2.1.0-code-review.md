# V2.1.0 Code and Flow Review

## Module boundaries

- `app.workspace` defines Gradio pages and wires UI values to backend callbacks.
- `app.app` owns UI-facing dataset import, configuration, training-subprocess monitoring, experiment browsing, and inference adapters.
- `uatf.config` resolves GUI, CLI, and Python API configurations through one schema.
- `uatf.cli` owns command-line dispatch and `uatf.tasks.lifecycle` persists task state and cooperative stop requests.
- `uatf.experiment` builds datasets and models, runs the shared `Trainer`, writes experiment records, and registers model assets.
- `uatf.data` owns CSV/folder datasets, inspection, transforms, deterministic splitting, and DataLoader construction.
- `uatf.evaluation`, `uatf.inference`, and `uatf.experiments` share saved model configuration and artifacts for evaluation, prediction, and history.

The module separation between the UI, config schema, training engine, data, models, evaluation, inference, and task lifecycle is retained. A broad rewrite of the existing CLI/API boundaries would add migration risk without improving the identified user path. `app.app` remains a large UI backend and is a candidate for later extraction into dataset, training, and model-asset services once its callback contracts are stable.

## Upload and training call flow

1. The dataset page selects either a ZIP upload or a server-local path.
2. ZIP import validates archive paths and file types, checks the expanded-size and free-space limits, extracts into a content-addressed cache, and records progress.
3. Inspection validates format, split settings, labels, paths, optional image contents, and train/validation viability. It stores the settings that must still match when training starts.
4. The training callback validates numeric controls, task and format, warning acknowledgement, the inspection-state fingerprint, and the shared config schema before returning its first status. Invalid requests do not create a task record or navigate to monitoring.
5. Valid config is written and passed to the UATF CLI in a child process. Structured events update the UI while the task lifecycle record, experiment record, checkpoints, metrics, and model asset persist to disk.
6. Evaluation and inference load the preprocessing values from the model asset so resize behavior matches training.

## Findings addressed

- Blank image-size input reached an unconditional `int(None)` in a Gradio callback and also failed independently during import and training. Resize now has an explicit boolean setting, and the enabled-size input returns a readable validation message when blank.
- Training previously yielded a preparation state before validating settings. The UI then routed to monitoring and surfaced invalid input asynchronously. Validation now precedes the initial UI status and uses the shared config resolver.
- Resizing is a per-sample transform, not an offline operation. With the former default of zero DataLoader workers, decoding and resize ran serially. Worker count is configurable, worker processes persist across epochs, and CUDA transfer can overlap pinned-memory copies.
- Turning resize off previously had no compatible batch contract. The loader now pads variable spatial dimensions per batch for dynamic-size convolutional adapters, while config validation rejects this option for ViT.
- Folder inspection performed a second recursive walk solely to locate nested split directories. That detection now runs during the existing file walk.
- ZIP extraction previously had a fixed 20 GiB ceiling and no destination free-space check. The cap is now 128 GiB, with free-space validation before extraction.

## Operational review

- At review time, no live UATF process was accessible. A persisted task for `experiment_018` pointed to a dead PID and had stopped updating at epoch 2 of 3. Its stale record was reconciled to `Failed`; the last checkpoint and logs were preserved.
- The existing architecture supports local image-folder and CSV classification datasets, single-label and multi-label classification, CPU/CUDA training, checkpoint resume, evaluation, and single/batch inference. Detection, segmentation, distributed training, stratified/group-aware splitting, and fully content-hashed datasets remain outside the supported scope.
- A focused end-to-end regression caught and fixed a no-resize inference failure: directory datasets return image-only samples, so their collate function must not unpack labels. Training, labeled evaluation, and image-only batch inference now have separate collate contracts.
- The workspace start callback was exercised with a real CLI subprocess. An unacknowledged class-coverage warning synchronously rejects the request; after acknowledgement, the task completes and writes its best checkpoint.
- Automated results are recorded in the release notes. The local Gradio server returned HTTP 200 and its 299-component configuration built, but the browser automation helper failed twice to activate Edge (`failed to activate captured window`); manual browser interaction remains unverified.
- The host does not contain a representative 50 GB test dataset, so no 50 GB throughput claim is made. DataLoader parallelism and optional resizing address the identified serial preprocessing path, but the optimal worker count remains hardware- and storage-dependent.
