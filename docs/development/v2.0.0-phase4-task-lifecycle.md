# UATF V2.0.0 Phase 4：训练任务生命周期与断点恢复

## 当前实现审查

训练引擎原有 `Trainer.resume()` 已能恢复模型、优化器、调度器、epoch、最佳监控值、早停、AMP scaler、Torch/CUDA 随机状态和 DataLoader generator 状态。原检查点没有累计训练历史或任务/数据兼容信息，训练循环也没有协作式停止入口。GUI 通过 CLI 子进程启动训练，但此前没有持久任务 ID、任务互斥或刷新后的查询接口。

## 本阶段修改

- `uatf/tasks/lifecycle.py` 与 `uatf/tasks/__init__.py`：按输出根目录持久化 JSON 任务记录，提供状态转换、内核文件锁、停止标记和异常退出识别。
- `uatf/api.py`、`uatf/cli.py`、`uatf/experiment.py`：由 Python API 统一创建任务和持有互斥锁；CLI 接收任务 ID、处理 Ctrl+C 停止请求；实验执行器更新实验目录和训练/验证状态。
- `uatf/training/trainer.py`：在完整训练与验证 Epoch 后响应停止，保留最近有效检查点；检查点新增完整 epoch 历史、任务类型、标签顺序和数据/预处理/模型兼容元数据。
- `app/app.py`：显示任务 ID，增加状态刷新与停止操作，页面加载时查询最近任务。
- `tests/unit/test_task_lifecycle.py`、现有 API/GUI 测试和训练集成测试：覆盖状态转换、互斥、停止、异常退出、恢复历史及兼容性；新增真实 CLI 子进程的 GUI 停止与恢复端到端验证。

## 设计决策

- 当前采用单任务策略，同一输出根目录一次只能有一个 UATF 训练任务。内核文件锁在训练进程异常退出时自动释放。
- 停止在完整 Epoch（训练及验证）边界生效。部分 Epoch 不写入可恢复检查点；已完成 Epoch 的 `last_model.pth` 和日志会保留。停止后不写成功评估报告，也不报告为 Completed。
- 暂停/继续仍未实现。断点恢复仅从最近完整 Epoch 检查点恢复。
- 旧版完整检查点仍可恢复；只有模型权重的文件继续被拒绝为完整 Trainer 状态。历史检查点缺少新兼容元数据时按原有结构/优化器等校验继续读取。
- 恢复报告包含检查点保存的历史 Epoch。数据集划分、预处理、模型、任务类型或标签顺序不匹配时拒绝继续。
- GUI 与训练 CLI 是独立进程。GUI 重开后从任务记录查询；训练 PID 已退出但状态仍活动时显示 Failed，并写入进程中断摘要。

## 限制与下一阶段前置条件

停止延迟最长约为当前 Epoch 的训练加验证时间。进程被强制终止时不会执行应用层清理，但系统释放进程设备资源及内核文件锁，最近一个完整检查点仍可用。此阶段不做持久化 GUI 历史列表、后台任务服务化或暂停功能。Phase 5 可在本生命周期与恢复接口之上继续扩展。
