# UATF 开发规范

## 1. 项目

项目名称：

通用 AI 训练框架 (Universal AI Training Framework)

缩写：

UATF

代码仓库：

universal-ai-training-framework

## 2. 项目目标

UATF 是一个可复用的 AI 模型训练框架，初期重点关注：

* 图像分类
* 多标签图像分类

该框架最终应支持：

数据集 (Dataset)
→ 模型 (Model)
→ 训练 (Training)
→ 验证 (Validation)
→ 评估 (Evaluation)
→ 检查点 (Checkpoint)
→ 配置 (Configuration)
→ 用户界面 (UI)

## 3. 开发理念

保持项目：

* 简洁
* 模块化
* 易于理解
* 易于测试
* 易于扩展

避免过度设计。

优先采用能满足当前需求的最简单架构。

## 4. 用户技能水平

项目负责人正在学习：

* Python
* PyTorch
* AI 模型训练
* Git
* AI 辅助编程

因此，代码必须优先考虑：

可读性

可解释性

可维护性

而非不必要的抽象。

## 5. Codex 角色

Codex 是一名工程助手。

在实现非简单功能之前：

1. 检查现有代码仓库。
2. 理解当前架构。
3. 确定受影响的文件。
4. 解释拟采用的方案。
5. 然后进行实现。

不要盲目覆盖现有代码。

## 6. 最小化变更

仅修改与当前任务相关的文件。

除非必要，否则不要重构无关模块。

如果必须进行大规模重构：

在执行前说明理由。

## 7. 依赖项

引入新依赖项时必须说明：

* 为什么需要它
* 它解决了什么问题
* 现有依赖项是否能解决该问题

优先使用稳定且广泛使用的库。

## 8. AI 框架

主要深度学习框架：

PyTorch

首选生态系统：

torchvision

图像处理：

Pillow

数据处理：

NumPy
pandas

可视化：

Matplotlib

用户界面 (UI)：

Gradio

除非必要，否则不要引入其他框架。 ## 9. 数据集架构

数据集逻辑必须与以下部分保持分离：

模型 (Model)

训练器 (Trainer)

评估 (Evaluation)

用户界面 (UI)

理想情况下，应通过“数据集适配器 (Dataset Adapter)”集成新数据集。

## 10. 模型架构

应能够通过模型注册表 (Model Registry) 或工厂模式 (Factory) 选择模型。

训练器不应包含特定于模型的逻辑。

## 11. 训练架构

训练器应负责处理：

训练

验证

检查点 (Checkpoint)

恢复训练 (Resume)

调度器 (Scheduler)

可选的混合精度训练 (AMP)

训练器不应包含特定于数据集的逻辑。

## 12. 评估架构

评估应与训练过程保持分离。

支持：

分类

多标签分类

评估指标 (Metrics) 应具备模块化特性。

## 13. 配置

实验参数应优先使用配置文件。

避免硬编码以下内容：

数据集路径

学习率

批次大小 (Batch sizes)

训练轮数 (Epochs)

模型名称

## 14. 测试

每个新功能都应配备相应的测试或验证流程。

在未进行实际测试的情况下，不得声称某项功能正常工作。

## 15. GPU

开发机器配备了 NVIDIA RTX 5080 笔记本 GPU。

设计训练代码时应考虑 GPU 支持。

然而：

在实际可行的情况下，应保留回退到 CPU 运行的能力。

## 16. 错误处理

错误信息应易于理解。

优先使用如下信息：

"Dataset CSV is missing required column: image_path"（数据集 CSV 缺少必要列：image_path）

而非晦涩难懂的错误提示（在可行范围内）。

## 17. Git

除非明确要求，否则不要自动执行：

git commit

git push

git merge

在建议提交 (commit) 之前：

* 检查变更内容
* 检查测试情况
* 解释该提交的含义

适当时使用约定式提交 (Conventional Commits) 前缀：

feat:
fix:
docs:
refactor:
test:
chore:

## 18. 文档

实现重要模块时，请说明：

* 其功能作用
* 其存在目的
* 如何与其他模块交互
* 如何使用
* 局限性

## 19. 教育性要求

不要仅仅提供代码。实施完成后，请提供：

### 变更内容

### 变更原因

### 工作原理

### 关键要点

### 测试方法

### 后续改进建议

## 20. 测试要求

切勿声称：

“一切正常”

除非已实际成功执行了相关测试。

请区分以下概念：

* 代码分析
* 语法验证
* 单元测试
* 集成测试
* 实际训练测试

## 21. 范围控制

切勿过早引入以下技术：

* Kubernetes
* 分布式训练
* 微服务
* 复杂数据库
* 云基础设施
* React
* Vue
* Docker
* MLOps 平台

除非项目后续阶段明确要求使用这些技术。

## 22. 医疗 AI

最终的胸部 X 光竞赛属于工程/机器学习基准测试项目。

切勿声称具备医疗诊断功能。

应将模型输出视为机器学习预测结果，而非临床诊断结论。

## 23. 沟通风格

解释技术概念时：

使用通俗易懂的中文。

避免使用不必要的行话。

确需使用技术术语时：

请提供英文术语并附带简要解释。

在有助于理解的情况下，使用图表和示例。

## 24. 默认开发流程

针对每一项功能：

理解需求
↓
检查代码库
↓
制定计划
↓
实施开发
